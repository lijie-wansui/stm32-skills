# CubeMX 生成代码保护规则（外设审核视角）

## 目的

本文件规定 `stm32-peripheral` 如何识别、审核和保护传统 STM32CubeMX
工程中的配置文件与生成代码。本 Skill
的职责是**只读审核**，不是编辑或修补生成文件。

## 1. 文件分类

| 文件/区域                                                                                      | 本 Skill 权限 | 说明                                         |
|------------------------------------------------------------------------------------------------|---------------|----------------------------------------------|
| `Project.ioc`                                                                                  | 只读          | 用户在 CubeMX 中维护的配置源文件             |
| CubeMX 生成的 `Core/Src/*.c`、`Core/Inc/*.h`                                                   | 只读          | 以当前工程实际生成内容为准                   |
| `main.c`、`gpio.c`、`tim.c`、`adc.c`、`dma.c`、`spi.c`、`usart.c`、`can.c`、`fdcan.c`、`i2c.c` | 只读          | 不直接修补生成的初始化代码                   |
| `stm32xx_hal_msp.c`、`stm32xx_it.c`                                                            | 只读          | 保留 MSP 初始化和 IRQ 分发关系               |
| `USER CODE BEGIN/END` 区域                                                                     | 只读          | 固件 Skill 可按规则写入，本外设 Skill 不编辑 |
| `Drivers/` 下 HAL、CMSIS、启动及厂商库文件                                                     | 只读          | 不修改第三方/厂商代码                        |
| `App/`、`Control/` 用户维护代码                                                                | 不负责编辑    | 交给 `stm32-firmware`                        |

文件名称可能因 MCU 系列、CubeMX
版本和工程模板不同而变化，必须识别当前工程实际文件，不依赖固定文件清单。

## 2. 审核 `.ioc` 与生成代码

1.  读取 `.ioc`，确认用户配置意图。
2.  读取对应 `MX_*_Init()`、`HAL_*_MspInit()`、DMA/NVIC
    初始化及相关句柄。
3.  将配置意图与生成代码逐项对照。
4.  如果 `.ioc` 与生成代码不一致，记录具体外设、字段和代码位置。
5.  如果生成区存在手工修改痕迹，不自行覆盖；报告差异并提醒用户确认是否为有意补丁。
6.  不把 `USER CODE` 区域的自定义调用误判为 CubeMX
    配置参数，也不把它作为修改初始化参数的入口。

## 3. 配置需要改变时

本 Skill 只给出可执行的 CubeMX 修改建议：

- 页面名称。
- 外设实例。
- 字段名称。
- 当前值。
- 建议值。
- 修改原因及影响的引脚、时钟、DMA、NVIC 或触发关系。

由用户在 CubeMX 中手动修改并生成代码。随后重新审核
`.ioc`、生成代码和差异。不要直接编辑 `.ioc`、`MX_*_Init()` 或 MSP
初始化代码来代替 CubeMX 操作。

## 4. 与固件 Skill 的交接

若外设配置正确，但缺少应用层启动、回调、数据缓存或控制逻辑：

- 将需要实现的接口和调用位置说明给用户。
- 交给 `stm32-firmware` 在 `App/`、`Control/` 中实现。
- 如需接入 `main.c`，由固件 Skill 检查并使用当前文件中真实存在的
  `USER CODE` 区域。
- 本 Skill 不修改 `USER CODE` 区域，也不直接编写 HAL 回调。

## 5. 重新生成后的复核清单

- [ ] `.ioc` 已由用户保存，芯片型号和外设配置符合预期。
- [ ] 生成的初始化参数与 `.ioc` 一致。
- [ ] GPIO AF、时钟、DMA 请求、NVIC 和触发源没有意外变化。
- [ ] `USER CODE BEGIN/END` 区域中的用户接入代码仍然存在。
- [ ] 没有重复初始化或重复 IRQ/回调定义。
- [ ] 生成文件差异与本次 CubeMX 配置修改相符。
- [ ] 未把“生成成功”当作编译或硬件验证通过。

## 6. 完成标准

外设审核完成时，应给出配置结论、生成代码对应位置、需要用户在 CubeMX
修改的字段，以及重新生成后必须复核的内容。整个过程中保持只读。
