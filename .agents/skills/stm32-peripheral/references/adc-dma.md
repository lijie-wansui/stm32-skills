# ADC 采样与 DMA

## 1. 从采样链开始分析

ADC 不是孤立模块。先画出完整信号链：

```text
被测电压/电流
    ↓
分压 / 传感器 / 隔离放大器 / 运放 / 滤波 / 保护
    ↓
MCU ADC 引脚
    ↓
ADC 采样保持与转换
    ↓
EOC / IRQ / DMA
    ↓
App 数据处理或 Control 控制算法
```

需要确认：
- 模拟前端输出范围是否符合 ADC 输入范围。
- ADC 引脚是否为目标封装可用的模拟输入。
- 前端输出阻抗和 RC 滤波是否满足采样时间要求。
- 模拟地、参考电压、供电和保护是否合理。
- 采样值对应的物理量换算关系和标定参数。

ADC 分辨率不等于整条测量链精度。

## 2. ADC 配置核对

按目标芯片支持情况检查：
- ADC 实例和通道。
- 分辨率、数据对齐和数据格式。
- Regular/Injected 转换组。
- 单次/连续转换。
- Scan 模式和 Rank 顺序。
- Sampling Time。
- 外部触发源和触发边沿。
- EOC/EOS 等完成标志行为。
- Overrun 行为和错误处理。
- 校准流程及其 HAL API。
- ADC 时钟来源和允许频率。
- 过采样、硬件平均或双 ADC 模式（若该型号支持）。

F1/F4/G4 的 ADC 架构和 HAL 接口可能不同，不能照搬其他系列的 ADC 初始化代码。

## 3. 采样时间与模拟前端

ADC Sampling Time 不是转换总时间的全部。通常还需要加上 ADC 转换周期；具体公式和周期数以目标系列 Reference Manual/Datasheet 为准。

采样时间需要结合：
- ADC 输入源阻抗。
- 前级运放输出能力。
- RC 滤波网络。
- ADC 采样电容和采样开关特性。
- 目标精度和采样频率。
- 通道切换后的建立时间。

不能因为“采样越短越快”就把 Sampling Time 一律设为最小值。也不能只根据运放型号判断采样时间足够，应结合电路参数和数据手册。

## 4. 触发同步

如果 ADC 由定时器触发：
- 明确触发源是 TRGO、TRGO2、CC 事件还是其他内部触发。
- 核对该 ADC 实例是否支持所选触发源。
- 核对触发边沿。
- 确认定时器计数模式和触发事件发生时刻。
- 确认 ADC 转换时间能否在下一次触发前完成。
- 确认采样点相对于 PWM 开关沿的位置。
- 考虑模拟前端建立时间、开关噪声和采样保持窗口。

中心对齐 PWM 中，上数/下数、比较事件和更新事件可能在不同时间发生。必须按 Reference Manual 和实际波形确认采样点，不要只凭 CubeMX 下拉菜单名称判断。

## 5. Regular 与 Injected 组

两种转换组的触发、优先级和数据读取方式不同，是否使用取决于目标芯片和控制需求。

检查：
- 当前 MCU 是否支持目标触发模式。
- Regular/Injected Rank 数量和顺序。
- 外部触发源和边沿。
- 多通道转换所需总时间。
- 是否与其他 ADC 组或 DMA 争用资源。
- 转换完成标志和读取接口。
- HAL 对应 API 的启动和停止方式。

不要因为电力电子系统常用 Injected ADC，就在所有 MCU/所有采样任务中强制使用 Injected。

## 6. DMA 配置与数据布局

核对：
- 当前 MCU DMA 架构：Channel、Stream、DMAMUX 或其他机制。
- 外设请求映射和请求源。
- Peripheral-to-Memory 方向。
- Peripheral/Memory Data Width。
- Memory Increment。
- Normal/Circular 模式。
- DMA Priority。
- 缓冲区长度和 C 数据类型。
- 半传输/全传输中断是否需要。
- DMA IRQ 与 NVIC 配置。
- DMA 完成后数据的实际更新时间。

DMA 长度参数的单位由当前 HAL API 决定，不要一律按字节处理。

## 7. Circular DMA 与缓冲区

本节重点判断 DMA 缓冲区的数据分段、更新时间和覆盖窗口。ISR/回调代码、环形队列实现、生产者/消费者同步及 C 语言并发细节，统一由 `stm32-firmware` 的中断与 DMA 参考资料负责，避免把配置分析和代码实现混为一谈。

Circular DMA 适合连续采样，但必须明确：
- 缓冲区分几段。
- Half-transfer 和 Transfer-complete 分别代表哪段数据可用。
- CPU 处理一段数据时 DMA 是否可能覆盖它。
- 处理任务是否能在下一次覆盖前完成。
- 生产者/消费者索引如何同步。
- 数据是否需要复制到独立缓存。
- 是否存在 DMA 与 CPU 并发访问问题。

`volatile` 只能影响编译器访问优化，不会自动解决竞态、数据撕裂或缓冲区覆盖。

如果 MCU 有数据缓存，需按该芯片的缓存一致性要求处理；不能把带缓存 MCU 的做法机械套到无缓存芯片，也不能忽略实际存在的缓存。

## 8. 控制算法中的数据更新时间

对 FCS-MPC、电流环或快速控制算法，必须明确：
- 采样触发时刻。
- ADC 转换完成时刻。
- DMA 数据可用时刻。
- 控制中断进入时刻。
- 算法读取的是哪一组采样数据。
- PWM 新 CCR 值何时写入。
- 新 CCR 何时通过 preload/update event 生效。

建议画时序图，不要只写“ADC 采样后进入控制中断”。如果控制 ISR 等待 ADC 转换完成，应明确该等待属于有界、预期的同步流程，并检查超时/故障行为是否符合项目既定设计；不要擅自把等待改成复杂的异步框架。

## 9. 校准、启动和故障

核对：
- ADC 是否需要上电校准。
- 校准 API 是否适用于当前系列和 HAL 版本。
- ADC 是否先初始化再校准、再启动。
- DMA 是否先准备好再启动 ADC（按当前 HAL/触发结构确认顺序）。
- ADC overrun、DMA transfer error 和采样值异常如何暴露给上层。
- 停止和重新启动时是否需要清理状态。

不要编造统一的启动顺序；以当前 HAL 头文件/源文件和参考手册为准。

## 10. 输出审核结论

给出 ADC 实例、通道、引脚、分辨率、采样时间、触发源、转换组、DMA 模式、缓冲区布局和数据更新时间。标明哪些已由工程配置确认，哪些仍需原理图或实测支持。
