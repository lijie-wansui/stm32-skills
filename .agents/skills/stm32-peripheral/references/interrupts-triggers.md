# NVIC、中断、定时器同步与外设触发

## 1. 先画事件链

外设协同工作时，先画出完整路径：

```text
定时器/外部引脚/外设事件
        ↓
硬件触发输入或内部触发路由
        ↓
目标外设动作（ADC 转换、定时器启动/复位、捕获等）
        ↓
DMA / 中断标志
        ↓
IRQ Handler → HAL IRQ Handler → HAL Callback
        ↓
App / Control 处理
```

不是所有事件都需要 CPU 介入。若 MCU 支持硬件触发，应优先评估硬件链路是否能满足时序和确定性要求。

## 2. NVIC 优先级

核对：
- Priority Group。
- 抢占优先级和子优先级。
- 各 IRQ 的实际优先级。
- IRQ 是否使能。
- 外设中断源是否也使能。
- 中断是否可能互相嵌套。
- 高优先级 ISR 的最坏执行时间。

通常 NVIC 优先级数值越小，优先级越高；但优先级分组决定抢占优先级和子优先级如何分配。必须结合当前工程设置理解。

不要为了“重要”就把所有中断设成最高优先级。为 FCS-MPC 等实时控制中断安排优先级时，应同时考虑 ADC 数据就绪、PWM 更新、通信接收和硬件故障响应。

## 3. IRQ Handler 与 HAL 回调

核对调用链：
1. 向量表对应的 IRQ Handler 名称正确。
2. `stm32xx_it.c` 中调用了正确的 HAL IRQ Handler。
3. 外设中断源和 NVIC IRQ 均已使能。
4. HAL 回调签名与当前驱动一致。
5. 回调定义没有重复。
6. 回调是否运行在中断上下文。
7. 回调是否处理了正确的外设句柄。

不能只在 NVIC 中打勾就认定中断已经完整配置。

## 4. 定时器主从同步

使用 Master/Slave、TRGO/TRGI 或内部触发路由时，先核对目标 MCU 的内部触发连接表。

确认：
- 哪个定时器是 Master，哪个是 Slave。
- Master 的 TRGO 选择了哪个事件。
- Slave 的 ITRx 实际连接到哪个 Master 信号。
- Slave Mode 是 Reset、Trigger、Gated、External Clock 等哪一种。
- 触发边沿和计数器启动/复位行为。
- 是否需要 Master/Slave Mode。
- 初始化顺序和启动顺序。
- 是否需要同步更新事件。

ITR1 在不同定时器/不同系列中连接的信号可能不同。不能只看名称猜它连接到 TIM1 或 TIM2，必须查对应 Reference Manual 的定时器内部互连表。

## 5. ADC 与定时器触发

核对：
- ADC 实例支持哪些定时器触发源。
- 使用 TRGO、TRGO2、CCx 还是其他触发源。
- 触发边沿。
- 定时器事件相对 PWM 周期的位置。
- ADC 转换总时间。
- 数据何时由 EOC/DMA 提供给 CPU。
- 控制 ISR 何时读取该数据。

如果使用 PWM 中点采样，必须结合实际 PWM 计数模式、比较事件、模拟前端建立时间和功率电路开关状态确定采样点。

## 6. 触发、DMA 和中断的关系

一个事件可能：
- 直接启动外设转换。
- 触发 DMA 请求。
- 产生外设中断标志。
- 同时触发多个内部模块。

不要把“触发 ADC”“DMA 搬运完成”和“ADC 转换完成中断”当成同一个事件。逐项确认事件源和完成条件。

DMA 半传输、全传输、外设 EOC/EOS、定时器 Update、Capture/Compare 等标志的语义不同。

## 7. 事件频率与最坏执行时间

对每个周期事件记录：
- 事件源频率。
- 每个 PWM/控制周期触发次数。
- 是否会因中心对齐、RCR、边沿选择或重复触发产生多次事件。
- ISR 最坏执行时间。
- 更高优先级中断可能造成的延迟。
- DMA 数据准备完成时间。
- 下一个输出更新的截止时间。

如果一个 5 kHz PWM 的更新事件在每个周期触发两次，那么控制算法实际执行频率可能是 10 kHz；也可能通过重复计数器或事件选择改变节奏。必须按目标芯片确认，不得默认等于 PWM 频率。

## 8. 逐跳通信与立即响应

若项目需要多个 MCU 通过 CAN/UART 等逐跳通知并立即响应：
- 分开分析通信传输时间、接收中断延迟、Control 处理时间和下一节点转发时间。
- 明确报文是否排队、是否可能仲裁等待、是否有重发。
- 明确节点收到报文后是否能立即改变本地状态，还是必须等待本地 PWM 安全更新点。
- 明确 CCR preload 和定时器更新事件是否限制输出真正生效的时刻。
- 明确通信事件不能绕过本地硬件故障保护和功率级安全约束。
- 对最坏延迟进行预算，不把“触发回调”当成“功率输出立即改变”。

## 9. 时序图要求

只要同时涉及两个及以上外设事件，建议画简洁时序图，标出：
- PWM 周期和计数方向。
- ADC 触发、采样窗口和转换完成。
- DMA 半传输/全传输。
- 控制中断进入/退出。
- CCR 写入和实际生效时刻。
- 通信接收、处理和转发时刻。

时序图中未测量的时间应标为理论估算或待测，不得编造硬件延迟。
