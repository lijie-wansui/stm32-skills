# TIM 定时器与 PWM

## 1. 先明确用途

先判断定时器承担什么任务：
- 基本定时和周期中断。
- PWM 输出。
- 互补 PWM。
- 输入捕获/频率测量。
- 输出比较。
- 编码器接口。
- 单脉冲。
- 外部触发、主从同步。
- ADC 触发。
- 多定时器相位错开或同步。

一个定时器可以支持多种模式，但具体功能取决于定时器类型、MCU 型号、通道和引脚。

## 2. 必须确认的时钟

不要直接把 SYSCLK 或 HCLK 当作 TIMxCLK。

检查：
- 定时器挂载的 APB 总线。
- APB Prescaler。
- 该系列是否存在定时器时钟倍频规则。
- 是否有独立定时器内核时钟或时钟选择。
- 当前 CubeMX 时钟树和 Reference Manual 的对应说明。

不同 STM32 系列的定时器时钟规则可能不同，不能将 F1/F4 的经验直接套到 G4。

## 3. 计数参数与 PWM 频率

对边沿对齐向上计数，常用关系为：

\[
f_{\mathrm{PWM}}=\frac{f_{\mathrm{TIM}}}{(PSC+1)(ARR+1)}
\]

对中心对齐计数，常见周期关系为：

\[
f_{\mathrm{PWM}}\approx\frac{f_{\mathrm{TIM}}}{2(PSC+1)ARR}
\]

实际计数边界、更新事件和计数模式应以目标 MCU Reference Manual 为准。特别是中心对齐模式下，不要把边沿对齐公式原样套用。

计算时：
- 明确 `PSC`、`ARR` 是寄存器值还是 CubeMX 显示值。
- 明确目标频率和定时器输入时钟。
- 计算后用实际生成参数反算频率。
- 注意计数器位宽和 ARR 范围。
- 如果目标频率无法精确整除，说明实际频率和误差。

## 4. 中心对齐模式

中心对齐 PWM 常用于降低特定开关谐波或实现对称开关时序，但 Mode 1/2/3 的比较标志行为并不相同。

必须确认：
- 具体 CMS 模式。
- 比较标志和中断标志在哪些计数方向/事件置位。
- 更新事件在上溢、下溢或重复计数器控制下的行为。
- 一个 PWM 周期内实际产生几次 Update Event/Update IRQ。
- CCR/ARR 预装载值何时传入活动寄存器。
- ADC 触发点是否处于预期计数方向和时刻。

如果控制算法放在 TIM 更新中断中，必须明确控制算法实际运行频率。不能只看 PWM 频率就认定 ISR 也是同一频率。

## 5. ARR/CCR 预装载与更新事件

ARR Preload 和 Output Compare Preload 的作用是让新参数先写入预装载寄存器，再在指定更新事件转移到活动寄存器，从而避免在计数周期中途改变比较值造成不期望的脉冲。

核对：
- ARR preload 是否开启。
- 每个使用的 CCR preload 是否开启。
- 更新事件何时发生。
- 软件更新事件、计数器上溢/下溢和重复计数器之间的关系。
- 是否使用 UDIS/URS 等更新事件控制位，以及它们对影子寄存器传输和中断的影响。

不要把“写入 CCR”直接等同于“引脚立即改变”。如果启用了预装载，新值通常要等到相应更新事件才生效。

不要在 App/Control 代码里随意修改 DIER、CR1 或 EGR 来弥补 CubeMX 配置问题；先弄清楚寄存器的系统影响。

## 6. 互补输出、死区和输出状态

如果使用高级定时器互补 PWM：
- 核对 CHx/CHxN 对应的 MCU 引脚和封装。
- 核对通道极性和互补输出极性。
- 核对输出空闲状态和 Idle State。
- 核对死区是否启用、实际编码和对应时间。
- 核对 Break 输入极性、滤波、锁定和自动输出使能等选项。
- 核对 MOE/输出使能的启动与关闭流程。
- 对照门极驱动器输入逻辑确认高低有效关系。

死区寄存器编码可能不是全范围线性计数；必须根据对应 Reference Manual 的 DTG 编码规则和定时器时钟计算。CubeMX 显示的时间值也要与生成代码/寄存器配置交叉核对。

死区不是越大越安全。过大死区会增加波形失真和损耗；过小则可能产生桥臂直通风险。最终值需要结合功率器件、驱动传播延迟、关断/开通特性和示波器实测确定。

## 7. Break 与故障保护

对于支持 Break 的定时器：
- 确认 Break 输入来自哪里（外部引脚、内部 COMP 等）。
- 确认信号有效电平和滤波。
- 确认故障时输出状态。
- 确认 MOE 自动清除/恢复行为及 AOE 等选项。
- 确认故障解除后是否需要软件明确恢复。
- 确认门极驱动器是否还有独立的 RST/EN/FAULT 硬件链路。

不能只靠软件中断关闭 PWM 来替代硬件快速保护。不要在没有确认故障原因和硬件状态时自动重新使能功率级。

## 8. 定时器中断与重复计数器

当 TIM 用作控制周期中断：
- 明确中断源是 Update、Capture/Compare、Trigger 还是其他事件。
- 确认 NVIC 与定时器 DIER 对应位都正确。
- 检查 IRQ Handler 是否调用正确 HAL IRQ Handler。
- 检查回调签名、句柄判断和调用上下文。
- 确认一个 PWM 周期触发几次中断。
- 检查 ISR 最坏执行时间是否小于允许的执行窗口。
- 不在 ISR 中做无界等待、阻塞发送或长时间轮询。

RCR（重复计数器）会影响更新事件产生节奏，但具体装载和中心对齐行为必须查目标芯片 Reference Manual。不要根据某次工程的 RCR 数值推断其他系列的行为。

## 9. 输入捕获

用于测量温度脉冲、频率或外部周期信号时，核对：
- 输入引脚复用和输入极性。
- Direct/Indirect/TI1/TI2 选择是否符合信号接线。
- Prescaler 和 Input Filter。
- 计数器时钟和计数范围。
- 上升沿/下降沿配对方式。
- 捕获溢出和计数器回绕处理。
- 中断或 DMA 的数据处理方式。

输入捕获测得的是定时器计数差，换算成时间/频率前必须确认计数时钟和预分频。

## 10. 交付时给出的信息

至少给出：
- 定时器实例、时钟来源和计算后的 TIMxCLK。
- PSC、ARR、计数模式和目标/实际频率。
- PWM 通道、引脚、极性和输出状态。
- CCR/ARR preload 状态。
- 死区、Break 和 MOE 相关配置（若使用）。
- 中断源、实际 IRQ 频率和 RCR 作用（若使用）。
- 尚需示波器验证的波形项目。
