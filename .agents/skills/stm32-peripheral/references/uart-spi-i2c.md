# UART、SPI 与 I2C

本章给出核查框架。实际函数名、参数单位、回调和中断机制以当前工程 HAL 为准。

## 1. UART / USART

### 硬件与配置
- 确认 UART/USART 实例和 TX/RX 引脚复用。
- 核对外部设备逻辑电平、是否隔离、是否需要 RS-232/RS-485 收发器。
- 核对波特率、数据位、停止位、校验位和流控。
- 核对过采样设置、时钟源和实际波特率误差。
- RS-485 还需确认 DE/RE 控制和总线方向切换时序。

### 接收方式
根据数据特点选择：
- 阻塞轮询：低速、短事务且允许等待时。
- 中断接收：数据量较小或有明确帧边界时。
- DMA Normal：已知长度的数据块。
- DMA Circular：连续数据流。
- IDLE/Receive-to-Idle：适合不定长数据，但必须确认当前 HAL 版本是否提供对应 API 和回调。

不要假设 F1、F4、G4 的 HAL 都支持同名 Receive-to-Idle API。先查当前工程 `stm32xx_hal_uart.h/.c`。

### 数据处理
- 明确帧边界：固定长度、长度字段、分隔符、空闲间隔或协议状态机。
- DMA 缓冲区长度和 HAL 长度参数单位必须核实。
- 处理半传输/全传输或 IDLE 时，防止重复处理和覆盖。
- 回调中只做必要的数据提交，不执行耗时解析或阻塞发送。
- 明确 UART 错误、Overrun 和重新接收策略。

## 2. SPI

### 硬件与配置
- 确认 SPI 实例、SCK/MISO/MOSI/NSS 引脚。
- 确认 Master/Slave。
- 核对 CPOL、CPHA 与从设备时序图。
- 核对数据宽度、MSB/LSB First、NSS 管理和时钟分频。
- 核对最大 SPI 时钟、上升/下降沿、片选建立/保持时间。
- 核对电平、隔离器和总线负载。

CPOL/CPHA 不要凭设备名称猜，应从从设备 Datasheet 的 SPI Timing Diagram 判断。

### 传输生命周期
- 轮询、中断和 DMA 按数据量、实时性和 CPU 占用选择。
- DMA 完成不一定意味着最后一位已经从 MOSI 发送完成。
- 释放 CS 前，按当前 SPI 外设状态和 HAL 语义确认总线物理传输完成。
- 核对 TX/RX 同步关系；全双工 SPI 传输通常同时产生接收数据。
- 确认 DMA 缓冲区在传输期间持续有效。
- 检查错误标志、Busy 状态和停止/复位流程。

不同 STM32 SPI 外设版本和 HAL 版本可能使用不同状态标志和完成机制，不能把其他系列的 BSY/ EOT 处理代码直接复制过来。

## 3. I2C

### 硬件与配置
- 确认 I2C 实例和引脚复用。
- 检查 SDA/SCL 上拉电阻是否存在、阻值是否适合总线电容和速率。
- 核对总线电压与所有器件逻辑电压兼容。
- 核对 Standard/Fast/Fast-mode Plus 等速率能力。
- 核对模拟/数字滤波设置（按目标外设支持情况）。
- 检查多器件地址是否冲突。

I2C 通常为开漏结构，不能把 SDA/SCL 配成推挽输出代替总线上拉。

### 地址和事务
- 明确器件地址是 7-bit 还是 10-bit。
- HAL API 对地址参数的传入格式可能有特定约定；必须查当前工程 HAL 头文件和示例，不能凭记忆决定是否左移。
- 核对寄存器地址宽度、大小端、Repeated Start 和 Stop 条件。
- 检查写寄存器、读寄存器和连续读的设备时序要求。
- 核对 ACK/NACK、Busy、Timeout 和总线错误状态。

### 总线异常
遇到 SDA 被拉低、Busy 或通信失败时，先判断：
- 供电和地是否正常。
- 上拉是否存在。
- 器件是否掉电或复位中。
- 地址、速率和时序是否正确。
- 是否有器件在事务中途保持 SDA/SCL。
- 是否存在电平不兼容或总线电容过大。

总线恢复操作必须根据实际器件和总线状态决定，不要在每次 I2C 失败时无条件切 GPIO 打时钟。

## 4. 三种通信外设的共通规则

- HAL API、回调、长度单位和错误状态均以当前工程版本为准。
- 外设初始化与启动传输是两个不同步骤。
- DMA/中断传输期间，缓冲区必须保持有效。
- 需要明确数据帧格式、字节序和协议边界。
- 回调上下文中避免阻塞、延时和复杂业务处理。
- 不能只凭软件返回 HAL_OK 就认定外部器件已经正确响应；必要时用逻辑分析仪或示波器验证引脚时序。
