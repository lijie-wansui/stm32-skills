# 工程识别与项目盘点

## 目标

识别当前工作区中真正需要分析的 STM32 工程，建立工程文件地图，并区分用户代码、自动生成代码、第三方库和构建产物。不要一开始就递归阅读所有文件。

## 1. 确认工程根目录

优先检查：
- 项目级 `AGENTS.md` 及其适用的上级指令。
- `README.md`、项目说明、开发记录。
- `.ioc`、`main.c`、启动文件和设备头文件。
- IDE 工程文件、构建文件和链接脚本。
- 原理图、PCB、BOM、硬件版本说明。

常见工程入口：
- STM32CubeMX：`.ioc`
- STM32CubeIDE：`.project`、`.cproject`
- Keil MDK：`.uvprojx`、`.uvoptx`
- IAR：`.ewp`、`.eww`
- CMake：`CMakeLists.txt`
- GNU Make：`Makefile`
- 其他工程：以实际构建说明和配置文件为准

这些文件可能同时存在，也可能有旧版本或迁移遗留。不能只凭某个文件存在就认定它是当前唯一有效入口。

若同一工作区有多个 `.ioc` 或多个 IDE 工程，先根据 README、目录关系、源码引用和用户任务判断；无法可靠区分时，向用户确认。

## 2. 建议的盘点顺序

1. 根目录文件和一级目录。
2. 项目说明与 `AGENTS.md`。
3. `.ioc` 和 IDE/构建工程文件。
4. `Core/`、`Drivers/`、`App/`、`Control/`、`BSP/` 等源码目录（目录名因工程而异）。
5. 启动文件、系统初始化文件、设备头文件和链接脚本。
6. 原理图、PCB、BOM、接口说明和芯片资料。
7. 必要时再追踪某个外设或函数的具体调用链。

输出工程目录树时，保留有意义的目录层级，不要把数百个中间文件全部展开。

## 3. 需要识别的文件类型

| 类型 | 常见文件/目录 | 识别目的 |
| --- | --- | --- |
| MCU 配置 | `.ioc` | 芯片选择、引脚、时钟、外设和 CubeMX 项目设置 |
| IDE 工程 | `.project`、`.cproject`、`.uvprojx`、`.ewp` | 工程组、源文件、宏、包含路径和目标设置 |
| 构建配置 | `CMakeLists.txt`、`Makefile`、构建脚本 | 实际构建目标、源文件、编译器和参数 |
| 启动文件 | `startup_stm32*.s`、`startup_stm32*.S` | 向量表、复位入口和目标设备 |
| 设备头文件 | `stm32xxxx*.h` | 寄存器定义、设备型号宏和外设实例 |
| 系统文件 | `system_stm32*.c/.h` | 系统时钟相关默认配置和 CMSIS 系统接口 |
| HAL/CMSIS | `Drivers/`、`Middlewares/`、Pack 路径 | 驱动版本和软件组件 |
| 链接配置 | `.ld`、`.sct`、`.icf` | Flash/RAM 区域、段布局和启动映像 |
| 用户代码 | `.c/.h`、汇编文件 | 应用、控制、驱动和项目逻辑 |
| 硬件资料 | `.pdf`、EDA 工程、BOM、PCB 导出文件 | 芯片、引脚和板级连接关系 |

## 4. 区分源码与构建产物

通常不需要逐个阅读：
- `Debug/`、`Release/`、`build/`、`out/` 中可重新生成的中间文件。
- `.o`、`.d`、`.elf`、`.map`、`.hex`、`.bin` 等构建产物。
- `.git/` 内部对象和索引文件。
- IDE 工作区缓存和临时文件。

但如果用户明确要求检查某次构建的 map 文件、ELF 符号或固件映像，则它们可能成为必要证据，应按任务读取，不要一概排除。

不要把整个 `Drivers/` 或 `Middlewares/` 目录当作用户代码。先识别其来源、版本和项目实际引用范围。

## 5. 区分代码来源

为重要文件标记来源：
- CubeMX/CubeIDE 生成。
- ST 官方 HAL/CMSIS 或中间件。
- 第三方库。
- 用户编写。
- 来源不明或经过修改。

可参考文件头注释、生成标记、目录位置、Git 历史和工程说明。不能仅凭文件名判断来源。

CubeMX 生成文件中存在 `USER CODE BEGIN/END` 标记时，应记录用户代码区的位置；但不能据此假定标记之外的文件一定未被手工修改。需要修改前，应查看版本控制差异或与生成结果对照。

## 6. 安全与最小读取

- 不输出 `.env`、密码、令牌、私钥、云服务凭据等内容。
- 不执行来源不明的构建脚本、安装脚本或二进制文件。
- 不为了盘点工程而修改文件、格式化代码或运行自动生成器。
- 不因某个目录看起来过时就删除它。
- 如果项目资料不完整，列出缺少的文件，不用猜测补齐。

## 7. 工程盘点输出

最少给出：
- 工程根目录。
- 工程入口文件及是否存在多个候选入口。
- MCU 目标信息（未确认时标记）。
- IDE/构建系统（已确认时填写）。
- 主要源码目录和职责概览。
- HAL/CMSIS 来源或版本（有证据时填写）。
- 启动文件和链接脚本。
- 硬件资料位置。
- 文件冲突、缺失项和待核实问题。
