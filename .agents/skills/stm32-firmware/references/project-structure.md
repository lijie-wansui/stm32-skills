# 工程分层与文件组织

本页定义通用代码职责。它是组织约定，不是要求把已有正常工程强制改造成某个固定目录。先识别当前工程结构；只有新建工程或用户明确要求整理时，才按需采用示例目录。

## 推荐目录

``` text
Project/
├── Core/
│   ├── Inc/
│   └── Src/
│       ├── main.c
│       ├── gpio.c
│       ├── tim.c
│       ├── adc.c
│       └── stm32xx_it.c
├── App/
│   ├── Inc/
│   └── Src/
├── Control/
│   ├── Inc/
│   └── Src/
├── Drivers/
│   └── ...                 # CMSIS、HAL 等，实际路径以工程为准
├── Docs/
│   └── Reference/          # 当前 MCU 的数据手册、参考手册、勘误
├── Project.ioc
├── AGENTS.md
└── README.md
```

已有工程可能使用 `User/`、`BSP/`、`Application/`
或其他目录名称。不要仅为符合示例而批量移动文件。

## App：可复用功能模块

`App/` 放置可被不同项目或不同控制流程调用的功能模块和基础算法。

常见内容： - `key.c/.h`：按键扫描、消抖和按键事件。 -
`can_app.c/.h`：CAN 应用层收发、接收缓存、数据打包与解析。 -
`sogi.c/.h`：SOGI 计算及内部状态。 -
`pid.c/.h`、`pr.c/.h`：控制器计算。 -
`fcs_mpc.c/.h`：仅在接口和模型可复用时，放置候选状态预测、代价计算等基础算法；当前
CHB 项目的轮值时序、总电平协同、模式管理和节点业务仍属于 `Control/`。

模块接口通过 `.h` 暴露；内部变量和辅助函数尽量保持
`static`。通常一个独立功能对应一组 `.c/.h`
文件，不要求每个项目都建立所有模块。

App 可以依赖当前工程已初始化的 HAL 句柄，也可以因 MCU
或外设不同而调整底层实现；“可复用”指功能职责和接口清晰，不意味着
F103、F407、G474 的驱动代码必须完全相同。

App 不应反向依赖当前项目的 `Control/`，也不应把某个项目的控制时序、特定
ID 业务含义或临时调试流程写进通用模块。

## Control：项目专属控制逻辑

`Control/` 从工程开始就建立，放置当前项目的控制流程、策略和模块调用。

包括： - 系统运行状态和控制模式。 - App 模块初始化、参数设置及调用。 -
ADC 采样值如何进入控制算法。 - PWM 启停、输出更新和保护逻辑。 -
定时器中断中的项目控制流程。 - 模块间通信、协同和故障响应。 -
阶段性调试、测试以及最终正式控制逻辑。

例如级联 H 桥项目： - `App/sogi.c` 实现可复用的 SOGI 算法。 -
`App/fcs_mpc.c` 可封装通用候选预测/代价计算；若算法实现与当前 CHB
模型、节点状态或论文策略强耦合，则放在
`Control/`，不要为了抽象而强行拆分。 - `App/can_app.c` 实现通用 CAN
收发和缓存。 - `Control/control.c`
决定各模块何时运行、控制周期、单元更新时序、协同传播和通信数据如何参与系统控制。

`Control/` 可以调用 `App/`；通用 `App/` 不应依赖 `Control/`。

## main.c：系统入口

`main.c` 负责： 1. HAL 和系统初始化。 2. 系统时钟配置。 3. 按 CubeMX
生成结果初始化 GPIO、DMA、TIM、ADC、CAN 等外设。 4.
调用项目控制初始化入口，例如 `Control_Init()`。 5.
进入主循环，并按项目结构调用
`Control_Run()`；如果项目主要由中断驱动，主循环可承担其他任务或保持空闲。

示意代码仅表达职责，不规定具体初始化函数和顺序：

``` c
int main(void)
{
    HAL_Init();
    SystemClock_Config();

    /* 以下初始化项和顺序以当前工程生成代码为准。 */
    MX_GPIO_Init();
    MX_DMA_Init();
    MX_TIM1_Init();
    MX_ADC1_Init();

    Control_Init();

    while (1)
    {
        Control_Run();
    }
}
```

不要把完整控制算法、所有项目状态和大量全局变量堆积在 `main.c`。

## Core 与中断文件

- `Core/` 中的外设初始化文件由 CubeMX 生成和维护。
- `stm32xx_it.c` 保留正确的 IRQ Handler，并按 HAL 规定调用 IRQ Handler。
- 不重复定义同一个 IRQ Handler。
- 不在 IRQ Handler 中堆积复杂控制流程。
- 项目专属中断处理和控制逻辑放在
  `Control/`；可复用的外设接收或数据缓存功能可由 `App/` 提供接口。
- HAL 回调可以在适当的 App 或 Control
  源文件中实现，但必须确认回调签名、弱函数机制、注册机制及是否存在重复定义。

## CubeMX 生成文件保护与 USER CODE 区域

CubeMX 生成文件不是整份都可以随意编辑。必须区分生成内容与用户保留区域：

- `.ioc`：只读配置基线。外设参数由用户在 CubeMX 中修改。
- `Core/Src/`、`Core/Inc/` 中的
  `main.c/.h`、`gpio.c/.h`、`tim.c/.h`、`adc.c/.h`、`dma.c/.h`、`spi.c/.h`、`usart.c/.h`、`can.c/.h`、`fdcan.c/.h`、`i2c.c/.h`、`stm32xx_hal_msp.c`、`stm32xx_it.c`
  等生成文件：生成区只读。文件列表以当前工程为准。
- `/* USER CODE BEGIN ... */` 与对应 `/* USER CODE END ... */`
  之间：允许固件开发任务添加必要的用户接入代码，但不能改动标记本身，也不能修改标记之外的生成代码。
- `Drivers/` 下
  HAL、CMSIS、启动文件和其他厂商代码：保持原样，不直接打补丁。

### 推荐接入位置

先检查当前 `main.c` 中实际存在的用户代码标记，不要假定不同 CubeMX
版本完全相同。常见用法：

- `USER CODE BEGIN Includes`：加入项目头文件，例如 `control.h`。
- 外设初始化完成后的用户区域：调用 `Control_Init()`。
- `USER CODE BEGIN WHILE`：调用需要在主循环运行的 `Control_Run()`。
- 其他用户区域：仅用于必要且简短的项目接入代码。

完整业务逻辑、HAL 回调和算法实现放在 `App/` 或 `Control/`
的用户维护源文件中，不把函数实现堆进 `main.c`。`stm32xx_it.c`
中保留生成的 IRQ Handler 和 HAL IRQ 分发调用；项目业务优先由
`App/Control` 中的 HAL 回调承接。

### 明确禁止

- 修改 `MX_*_Init()` 中 CubeMX 生成的外设配置语句。
- 修改 `HAL_*_MspInit()` 中生成的 GPIO、时钟、DMA、NVIC 配置。
- 修改时钟树、GPIO AF、PWM/ADC 参数、DMA 请求、中断优先级或触发源来绕过
  CubeMX。
- 修改、删除、移动或重命名 `USER CODE` 标记。
- 在没有标记的生成文件中自行插入 `USER CODE` 标记。
- 把用户代码区当作直接改寄存器、覆盖 CubeMX 初始化参数的入口。

如果没有合适的用户代码入口，先在 `App/` 或 `Control/`
新建用户维护文件，再向用户说明需要在 `main.c`
的哪个现有用户区域加入调用。不要直接改写生成区。

需要改变外设配置时，由用户在 CubeMX 手动修改并重新生成。生成后重新检查
`.ioc`、生成代码、用户代码区域和完整
diff，确认用户接入代码保留且配置变化符合预期。

具体文件判断、例外处理和重新生成检查步骤见 [CubeMX
生成代码编辑规则](cubemx-generated-code-editing.md)。

## 不强制 Test 目录

不要求创建统一的 `Test/` 目录。项目调试、阶段性测试和最终控制逻辑统一由
`Control/`
管理。测试结束后删除不再需要的临时代码；确实具有复用价值的功能再整理进
`App/`。

## 修改文件前的归属判断

| 变更内容                     | 优先归属                                                      |
|------------------------------|---------------------------------------------------------------|
| 可复用算法或功能             | `App/`                                                        |
| 项目专属控制状态、时序和策略 | `Control/`                                                    |
| CubeMX 外设配置              | 用户在 CubeMX 中修改 `.ioc` 并生成；生成代码由 Agent 只读审核 |
| 系统启动与主循环入口         | `main.c`                                                      |
| HAL IRQ Handler 的底层分发   | `stm32xx_it.c`                                                |
| 项目回调中的业务处理         | `Control/` 或对应 `App/` 模块                                 |

若某项功能的归属不清楚，先解释职责边界并提出建议，不要未经确认批量移动文件。
