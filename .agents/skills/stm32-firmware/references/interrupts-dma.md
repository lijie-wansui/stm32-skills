# 中断、HAL 回调与 DMA

本页提供核查框架。不同 MCU、HAL 版本和外设的具体
IRQ、回调名称、参数及启动流程必须从当前工程核实。

## 中断入口与回调分层

典型调用关系：

``` text
外设中断
   ↓
芯片 IRQ Handler（通常位于 stm32xx_it.c）
   ↓
HAL 外设 IRQ Handler
   ↓
HAL 内部状态处理
   ↓
HAL 用户回调
   ↓
App 或 Control 中的项目处理函数
```

- `stm32xx_it.c` 中的 IRQ Handler 通常由 CubeMX
  生成，生成区受保护；保留正确的向量名称和 HAL IRQ Handler
  调用，不直接改写 Handler 分发逻辑。
- 项目业务优先通过 `App/` 或 `Control/` 中经当前 HAL
  版本核实的回调函数实现；不要把控制算法直接塞入生成的 IRQ Handler。
- 不重复定义同一 IRQ Handler。
- 不随意改变中断分发链。
- HAL 用户回调可放在合适的 `App/` 或 `Control/`
  源文件中，但要确保只有一个有效定义。
- 通用外设缓存或接收逻辑可以由 App 模块提供；项目专属动作由 Control
  决定。

## 先核对回调机制

编写回调前，检查当前 HAL： - 回调函数准确名称和完整参数列表。 -
回调是否为弱函数。 - 当前驱动是否支持回调注册，以及对应配置宏。 -
注册回调的合法时机和返回状态。 -
回调是在中断上下文还是其他上下文执行。 - 对应 IRQ 是否使能，IRQ Handler
是否正确调用 HAL。

不能把某个系列的回调签名直接复制到另一个系列，也不能假定 HAL1 和 HAL2
使用相同的注册方式。

## 中断处理原则

- 中断中只执行实时性要求明确的必要工作。
- 避免在 ISR 中执行阻塞 HAL 调用、长时间等待、`HAL_Delay()`
  或复杂数据处理。
- 对较重的算法，考虑在 ISR 中保存数据或提交事件，再由 Control
  在合适的上下文处理；若控制时序明确要求在中断内执行，则依据最坏执行时间和中断优先级验证。
- 不要为了“架构统一”机械地把所有控制算法放主循环或全部放中断。
- 不在回调中无条件重新启动所有传输；先判断当前模式、完成事件和错误状态。

## DMA 启动前检查

逐项确认： - 当前 MCU 的 DMA 架构和外设请求映射。 - DMA
请求源、方向和关联的外设句柄。 - 外设与内存的数据宽度。 - Normal 或
Circular 模式。 - 缓冲区类型、容量、对齐要求和生命周期。 - DMA
完成、半传输及错误中断是否需要。 - 对应 NVIC 设置和 HAL 回调是否存在。 -
CPU 与 DMA 是否可能同时访问缓冲区。 -
当前芯片是否有数据缓存及相应一致性要求。

不能仅凭另一个工程的 DMA Channel/Stream 常量复制配置。

## 缓冲区生命周期与长度单位

- DMA 传输期间，缓冲区必须保持有效，不能传入即将离开作用域的局部数组。
- 明确 DMA 是读取缓冲区还是写入缓冲区。
- 检查缓冲区长度是否与真实容量匹配。
- 核对具体 HAL API
  的长度参数单位；不同外设可能使用字节数、数据项数、转换数或帧数。
- Circular DMA
  要按半传输/全传输/位置指针等机制正确计算新数据，防止重复处理或覆盖未消费数据。
- Normal DMA
  完成后是否重新启动，由协议和业务决定，不要在每个回调里无条件重启。

## DMA 完成不一定等于外设物理传输结束

例如某些 SPI 传输中，DMA
已经把最后一个数据写入外设数据寄存器，但最后一位可能仍在移位寄存器中发送。需要根据外设状态和
HAL 语义判断何时可以释放片选或复用缓冲区。

对 UART、SPI、ADC 等分别核对其完成语义，不能把“DMA
完成”笼统理解为“外设全部工作结束”。

## 并发和队列

如果 ISR/DMA 回调生产数据，主循环或 Control 消费数据： -
明确生产者和消费者。 - 明确索引或状态变量的更新顺序。 -
检查访问是否原子、是否需要临界区或其他同步方式。 -
明确缓冲区满、数据丢失和覆盖策略。 - 不用 `volatile` 代替并发同步。 -
不为简单单生产者/单消费者场景机械引入复杂 RTOS 队列或消息框架。

## 编译与硬件验证

代码审查时先核对 HAL
API、宏、句柄、回调和缓冲区，再进行构建。实际硬件验证时观察： - IRQ
是否按预期进入。 - 回调是否只触发预期次数。 - DMA
数据顺序、长度和更新时间是否正确。 - 是否出现 overrun、busy、transfer
error 或丢帧。 - 异步传输结束后外设和缓冲区是否处于预期状态。

编译通过不能替代中断时序、DMA 数据完整性和真实外设波形验证。
